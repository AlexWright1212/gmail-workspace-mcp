# Architecture Decision Records

| ADR | Decision |
|---|---|
| [001 — Initial Architecture](001-initial-architecture.md) | Deploy `tszaks/gmail-multi-inbox-mcp` on a $6/mo DigitalOcean VPS over SSE, rather than a single-account official connector, a local stdio server, or Cloudflare Workers. Send capability deleted from source entirely; bearer auth, `tools-enabled.json`, and OAuth scope restriction as layered defenses. Predates gated sending — see 004 for the boundary as it works now. Origin: ad hoc. |
| [002 — Remove `unsubscribe_from_email`](002-remove-unsubscribe-tool.md) | A blind SSRF: the tool auto-POSTed to a URL from the incoming email's attacker-controlled `List-Unsubscribe` header. Deleted outright rather than sanitized; unsubscribing is now out of scope in the spec. Origin: ad hoc (adversarial review). |
| [003 — The exposed-tool config fails closed](003-tools-enabled-fails-closed.md) | `endpoints.json` (was `tools-enabled.json` until 2026-09-19) is the only thing deciding which tools each endpoint exposes, out of the 60+ built into the code. A load failure used to enable every tool, then none; since plan 002 Phase 1 `loadEndpoints()` in `src/endpoints.ts` refuses to boot on any malformed file, unknown tool name, or duplicate path, because an empty two-endpoint server passes the deploy health check. Read/write scope classification is derived from each tool's `annotations.readOnlyHint`, not a separate map. Origin: ad hoc; amended under plan 002. |
| [004 — Extend the allowlist to Drive/Calendar](004-extend-allowlist-to-workspace-tools.md) | `share_drive_file` and `create_event`/`update_event` can email third parties via Google but never checked the send-allowlist. The same allowlist is now wired into all three, and `share_drive_file` refuses `type: "anyone"`/`"domain"`. Amended 2026-09-19: `create_event`/`update_event` now exposed on `/workspace/mcp` with the same unchanged gate, proven by `test/workspace-write-drive-calendar.test.mjs` and the live harness; `share_drive_file` stays unexposed. Origin: ad hoc. |
| [005 — Disable Gmail signature reuse](005-disable-gmail-signature-reuse.md) | The Gmail API exposes only a signature set as the account *default*, and setting one makes Gmail auto-insert it into every web compose. Disabled rather than change the owner's email behavior; the code path is dormant and `test/signature-disabled.test.mjs` enforces it structurally. Spec updated to match. Origin: ad hoc. |
| [006 — The spec and the ADRs are living documents](006-living-spec-and-adrs.md) | The spec is synced on the owner's confirmation whenever divergence appears; ADRs are grouped by topic and edited in place, with `**Last edited:**` bumped on every edit. Reverses the append-only rule 002 and 005 were written under. Origin: ad hoc. |
| [007 — Tailscale-only SSE endpoint](007-tailscale-only-sse-endpoint.md) | **Superseded by 012; fully unwound 2026-08-30 when `/sse` was deleted.** Moved the then-public plaintext SSE endpoint onto the tailnet instead of adding TLS. The instinct survives for the admin path: SSH is tailnet-only today. Origin: ticket 002. |
| [009 — Attachment outbox for client-side files](009-attachment-outbox-for-client-side-files.md) | `readAttachment()` runs on the VPS, so a file on the caller's laptop is unreachable. Added a drop-box directory (`/root/.gmail-multi-mcp/outbox`) filled over the existing deploy SSH access, read once and deleted. Rejected inlining base64 and running locally over stdio. Amended 2026-09-19: the resolver moved to `src/outbox.ts` and `upload_drive_file` shares the drop box under a stricter must-be-inside rule, because a Drive upload has no MIME/allowlist gate. Origin: ad hoc. |
| [010 — VPS access: outbox, audit log, ad-hoc commands](010-outbox-and-audit-log-permission-carve-out.md) | Carved two routine paths (`scp` into `outbox/`, read-only `send-audit.log`) out of the blanket permission rule protecting `/root/.gmail-multi-mcp/`, and added `scripts/vps.sh` as the sanctioned ad-hoc command path. `autoMode.soft_deny` is classifier guidance, not a hard deny; the real boundary is possession of the deploy key. Origin: ad hoc. |
| [011 — What the server tells a model about accounts](011-account-context-and-health.md) | Account map, the read-both/write-explicit asymmetry, and the allowlist boundary moved into the server's top-level `instructions` string, because Claude Code defers tool descriptions but never `instructions`. No account health reporting of any kind: `list_accounts` stays disabled, and aggregate reads already name a failing account under an `INCOMPLETE` banner — on both endpoints since plan 002 Phase 5 (Workspace lists used to trail an "Account Errors" section). Origin: ticket 004. |
| [012 — Public Streamable HTTP via Cloudflare Tunnel](012-public-streamable-http-via-cloudflare-tunnel.md) | **Supersedes 007.** Stateless `/mcp` endpoint behind a named Cloudflare Tunnel — zero inbound ports, at the accepted cost of Cloudflare decrypting in transit. Statelessness and `GET`/`DELETE /mcp` → 405 are load-bearing (Cloudflare's 125s proxy timeout, an SDK stream-loss bug). `/sse` and `/messages` were deleted 2026-08-30; `/mcp` is the only transport. Origin: plan 001. |
| [013 — Self-hosted OAuth 2.1 authorization server, Google upstream](013-self-hosted-oauth-google-upstream.md) | Self-hosted AS delegating login to Google, restricted to the owner's two addresses, with a mandatory consent screen naming the requesting client (added after adversarial review found a phishing exploit via open DCR). Since 2026-08-30 OAuth is the only credential: the `/mcp` gate denies all when unconfigured and the server refuses to boot on HTTP without it. Origin: plan 001. |
| [014 — Cloudflare API access: scoped, extensible token](014-cloudflare-api-access-scoped-token.md) | A scoped Cloudflare token, extended only on a tested need, reached through `scripts/cloudflare-api.sh` and `~/.config/gmail-mcp/cloudflare.env` outside the repo. Origin: plan 001. |
| [016 — Two endpoints, one authorization server](016-two-endpoints-one-authorization-server.md) | Each `endpoints.json` entry is its own OAuth protected resource (`verifierFor(url)` in `src/http/oauth/provider.ts`; a Mail token is a 401 at Workspace), with its own metadata document and consent-page name (`displayName`). Scopes are `read`/`write` on both; the `mail:*` alias that carried old tokens across the rename was deleted 2026-09-20 (Phase 6) after `clients.sh migrate-scopes` rewrote the stored records, and a retired name now fails closed. Surprising: existing clients needed no re-consent, and the alias's own removal gate ("no LEGACY client") could never have closed without that rewrite. `deploy.sh` probes every endpoint's metadata through the tunnel, closing the ingress-drift class. Origin: plan 002, Phase 2. |
| [017 — Read/write scope classification from `readOnlyHint`](017-read-write-scope-classification.md) | `read`/`write` (the scope names ADR 016 introduced) are derived per tool from `annotations.readOnlyHint` on the tool definition (`scopeForTool()` in `src/http/scopes.ts`), not a separate hand-maintained map — a tool missing the flag is denied at runtime and fails `test/registry.test.mjs` at build time. `read` forbids every mutation, including creating a draft/doc/tab/event. `test/workspace-endpoint.test.mjs` pins the 22 Phase 4 write tools as exactly the `readOnlyHint:false` set. Origin: plan 002, Phase 2 (mechanism); Phase 4 (write set pinned). |
| [018 — Tab-addressed Docs reads and anchored Docs writes](018-tab-addressed-docs-reads-and-anchored-writes.md) | Every Docs read walks `tabs[]`/`childTabs[]` with `includeTabsContent: true` and renders per tab (`src/docs/tabs.ts`); above 60,000 characters (a guess) it returns a tab index instead of truncating. Every write names a tab (`resolveTargetTab` in `src/docs/writes.ts`, "the tab rule") and pins its `batchUpdate` to `writeControl.requiredRevisionId` from the same read. Anchors (`src/docs/anchors.ts`, ported from a-bonus's `findElements`) are resolved at call time and refused on 0 or >1 matches; anchors/find strings may not contain a line break. `docs_insert_table`/`docs_apply_style` deleted outright, no Markdown-to-Doc writer built or planned. Origin: plan 002, Phases 3 and 4. |
| [019 — Sheets header-row auto-detection](019-sheets-header-row-auto-detection.md) | `detectHeaderRow()` (`src/sheets/records.ts`) picks the widest row in the first 20 as the header, ties to the earliest — the owner's tracker has its real header on row 7, under a title and a totals block. `read_sheet_records`, `find_sheet_rows`, and `update_sheet_row` all call the same function with the same parameters so a read and the write that follows it cannot disagree about which row is the header. Still a heuristic: a wider data row would win. Origin: plan 002, Phase 3 (Phase 4 reuse in `update_sheet_row`). |
| [020 — Fixture-copy verification](020-fixture-copy-verification.md) | `tools/live/workspace-check.mjs` runs on the VPS through the deployed client (`rawApis()`, never a token file), copies the two Drive templates per account as `zz-test-<run id>-...`, calls the actual tool handlers, and pairs every assertion with an independent read-back; copies are trashed on success, kept (with ids printed) on failure. Calendar writes touch only the secondary "Google Testing" calendar. Surprising, confirmed live: `drive.files.copy` preserves Sheets data-validation rules; `values.append` aligns to the first header column, not column A; a deleted event reads back `status: cancelled`. Phase 5 added the agent-level layer on top (`tools/live/phase5-readback.mjs` + request-log diff), which found five wording/default/discoverability defects the harness could not. Origin: plan 002, Phases 3–5. |
| [015 — Per-client accountability: request log and `clients.sh`](015-per-client-accountability.md) | Per-client request log (`src/http/request-log.ts` — authenticated `/mcp` requests only, no secrets recorded) plus `scripts/clients.sh list\|revoke`, so one OAuth client can be traced and cut off without rotating everything. Revocation is operator-side only — deliberately no MCP tool for it. No body parser may ever be mounted on `/mcp`; the log reads parsed messages off the transport instead. Origin: plan 001, Phase 3. |
